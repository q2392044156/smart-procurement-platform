# 三分钟演示脚本

> 目标：在三分钟内讲清“这是什么系统、解决了什么问题、工程上做了什么取舍”。
> 建议 1280×720 录屏，1.25 倍速，鼠标高亮；不要展示 `.env`、密钥与任何真实账号密码。

## 0. 开场（0:00–0:25）

口播：

> 这是一个面向制造企业的采购与供应链系统，覆盖“申请 → 三档金额审批 → 转订单 → 分批收货 → 出库领用 → 库存 → 预算 → 合同”的闭环；
> 同时它预留了给 Agent 调用的内部工具面，业务系统和 Agent 在源码与运行时上解耦。

画面：停留在经营看板，展示待审批、低库存、趋势图。

## 1. 申请与审批（0:25–1:00）

1. 用 `requester` 登录 → 采购申请 → 新建：选物资、填数量与用途 → 保存。
2. 提交 → 提示进入审批；切到 `manager` → 审批中心，看到待办 → 详情 → 预览单据 → 通过。
3. 说明：5 万以下两级、5–50 万加财务、50 万以上加总经理；申请人兼审批角色时自动跳过。

## 2. 订单、收货与出库（1:00–1:45）

1. `purchaser` 登录 → 采购订单 → 从已批准申请转单（可改单价）→ 提交。
2. `finance` 审批通过 → `warehouse` 收货：分批数量、批次号/序列号校验。
3. 库存页：余额增加、流水写入；再演示“出库/领用”，余额扣减、流水出现 `ISSUE/OUT`。
4. 说明：收货/出库与库存入账同事务，余额乐观锁，写接口幂等。

## 3. 预算与合同（1:45–2:15）

1. `finance` 打开部门预算 → 调整某部门额度。
2. 用该部门申请人提交超额申请 → 被 409 拦截；调高预算后可提交。
3. 合同管理：新建合同 → 启用；展示“到期自动标记”和“关联订单供应商一致性校验”。

## 4. 知识库（2:15–2:40）

1. 管理员上传《采购管理制度》DOCX → 发布。
2. 换一个普通申请人账号：只能看到已发布文档，无维护按钮。
3. 说明：可见范围五档、版本历史、下载鉴权、删除保护；检索侧通过内部接口拿“可见文档 + 增量变更”。

## 5. 收尾与取舍（2:40–3:00）

口播：

> 工程上刻意做了几个取舍：用 Flowable 而不是自研状态机；全量 SQL 走 JdbcTemplate，不引 ORM；
> Agent 通过 `/api` 内部令牌 + 用户身份透传，权限和数据范围仍由平台判定；
> 写操作按内容指纹幂等，避免 Agent 重试重复建单。

画面：代码或测试结果（`mvn test`、Playwright 输出）快速带过。

## 录屏检查清单

- [ ] 不出现密钥、`.env`、真实个人信息
- [ ] 每个页面停留不超过 8 秒，重点讲“规则”而不是“点击”
- [ ] 结尾给出一句“当前边界”：未做询价/发票/质检，属于下一阶段
- [ ] 视频长度控制在 3 分钟内，超过则剪掉重复操作
